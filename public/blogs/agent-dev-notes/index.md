## Agent 是什么

Agent（智能体）可以理解为：**大模型 + 规划 + 工具 + 记忆** 的组合体。它不再只是"你问一句我答一句"，而是能接收一个目标，自主拆解步骤、调用外部工具、根据结果调整，最终完成任务。

## 核心概念

### 1. ReAct 循环
ReAct = **Reasoning（推理）+ Acting（行动）**。循环往复：

```
思考（Think）→ 行动（Act/调用工具）→ 观察（Observe）→ 再思考...
```

这是大多数 Agent 的底层骨架。模型在每一步先想"下一步该做什么"，然后执行工具调用，拿到结果后再继续。

### 2. 工具调用（Function Calling / Tool Use）
让模型选择调用哪个工具、传什么参数，代码来真正执行。关键设计：

- **工具注册表**：把工具名、描述、参数 Schema 告诉模型，模型据此挑选
- **参数校验**：模型输出的参数可能是错的，代码侧要校验
- **错误处理**：工具执行失败要回传给模型，让它尝试别的路径
- **权限边界**：危险操作（删库、发消息、付款）要人工确认

### 3. 记忆
- **短期记忆**：当前任务的上下文（对话历史、中间结果）
- **长期记忆**：跨会话的知识，通常用向量库 + 语义检索，或结构化存储
- 注意上下文窗口与成本：该压缩的压缩、该摘要的摘要

### 4. 多智能体（Multi-Agent）
把大任务拆给多个角色 Agent 协作：比如一个 Planner 负责拆解，多个 Worker 并行执行，一个 Critic 负责检查。收益是模块化，代价是协调与上下文传递更复杂。

## 主流框架

| 框架 | 特点 | 适合场景 |
|---|---|---|
| LangGraph | 图式编排，状态机，可控性强 | 生产级复杂流程 |
| OpenAI Agents SDK | 轻量、官方、上手快 | 快速原型 |
| LangChain | 生态大，工具多 | 通用场景 |
| 自研循环 | 用 Function Calling 手写 ReAct | 理解原理、完全可控 |

框架只是脚手架，**理解 ReAct 和工具设计才是核心**。

## 工程化要点

- **评测**：一个可重复的评测集比跑 10 次手动测试更有价值
- **可观测性**：记录每步的思考、工具输入输出，出问题才能定位
- **成本控制**：模型缓存、结果缓存、控制上下文长度
- **安全护栏**：系统提示词约束 + 工具权限 + 输出过滤

## 练手建议

1. 手写一个 10 行以内的 ReAct 循环（理解原理）
2. 给 Agent 加 2-3 个真实工具（搜索、计算、读写文件）
3. 加一个简单记忆模块
4. 再上一个框架对比一下体感差异
